このページはなにを学ぶpage？

AIにファイル編集やコマンド実行を任せる時代の**「AIに何をさせて、何をさせないか」を自分で決める技術**を学ぶ。道具は2つ：

  • Permissions（パーミッション）＝「やっていい／ダメ／要確認」の入館ルール表
  • Hooks（フック）＝特定のタイミングで必ず自動実行されるセンサー付き自動ドア

重要ポイント

PermissionsとHooksの違い（まずここだけ）

PermissionsHooks
例えるとマンションの入館ルール表センサー付き自動ドア
何をする実行を許可/拒否/確認に振り分け決まったタイミングでプログラムを自動実行
得意「このコマンド禁止」とシンプルに宣言中身を見て条件次第でブロックする細かい判断
  • 使い分けのコツ：まずPermissionsで禁止/確認リストを宣言し、細かい判断が必要なところだけHooksを足す。
  • ルールの評価順は deny→ask→allow で、最初にマッチしたdenyが必ず勝つ。

初級：最小の保護設定

  1. .claude/settings.json の permissions.deny に "Read(.env*)" を追加（AIに.envを読ませない）
  2. PreToolUse Hookで rm（削除コマンド）を実行直前に検知してブロック：
  1. 設定はセッション開始時に読み込まれるので、再起動してから動作確認する
  • 既知の不具合：一部バージョンでRead系denyが効かないことがある→PreToolUse Hookを保険として併用。

中級：公式プラグイン security-guidance

  • 入れるだけで、AIが書くコードの25種類以上の危険パターン（XSS・コマンドインジェクション等）を自動チェックし、その場でブロック・警告してくれる。
  • 動作確認は「わざと危険なコード（innerHTMLへの代入やeval）を書かせてみる」。

上級：実運用の保護設計（そのまま使える設計図）

区分例ねらい
allow（確認なし）build/lint/test/git status・diff・log安全な作業は快適に
deny（必ず止める）rm -rf／sudo／Read(.env*)／Read(/.ssh/)／psql・mysql等の本番DB直操作破壊・漏洩・本番事故を構造的に防ぐ
ask（毎回確認）rm／curl／chmod +x／git push・reset・rebase便利だが取り返しがつきにくい操作は人間が判断
  • Hooksは3つのタイミング：PreToolUse（実行前ブロック）／PostToolUse（実行後の自動整形・チェック）／Stop（終了前の最終チェック）
  • 保護マップ：「防ぎたい事故→どのレイヤーで防ぐか」を表にして設計する考え方が重要。
  • 完成した settings.json はGitにコミットしてチーム共有・他プロジェクトへ横展開する。
  • グローバル設定（~/.claude/settings.json）は全プロジェクトに効くので、入れすぎると普段の作業まで止まる。基本はプロジェクト設定から始め、本当に全体で禁止したいものだけ昇格。

用語解説

  • Permissions（パーミッション）：許可設定。「allow＝許可」「deny＝禁止」「ask＝実行前に確認」の3区分。
  • Hooks（フック）：「〜の直前/直後」に必ず実行される自動処理。フックは「引っ掛ける」という意味。
  • PreToolUse／PostToolUse／Stop：ツール実行の「直前」「直後」「応答終了前」のタイミング名。
  • rm -rf：フォルダごと全削除する危険コマンド。取り返しがつかない代表格。
  • sudo（スドー）：管理者権限でコマンドを実行すること。強力ゆえに危険。
  • XSS（クロスサイトスクリプティング）：Webページに悪意あるプログラムを注入される攻撃。innerHTMLへの無防備な代入が典型例。
  • コマンドインジェクション：入力欄などから不正なコマンドを実行させられる攻撃。
  • security-guidance：Anthropic公式の無料セキュリティチェックプラグイン。
  • プラグイン：後から追加できる拡張機能。
  • jq（ジェイキュー）：JSONデータを読み取る小さなツール。Hookの中身の検査に使う。
  • exit code 2：Hookが「ブロックする」ことをシステムに伝える終了番号。
  • SSH秘密鍵（id_rsa等）：サーバーに入るための鍵ファイル。漏れたらサーバーを乗っ取られる。
  • 本番DB：実際のお客様データが入っているデータベース。直接操作は事故のもと。
  • レイヤー：層のこと。「どの層（deny/ask/Hook）で防ぐか」という多重防御の考え方。

マネタイズへのヒント💰

  • 「AIに安全に仕事をさせる設計」ができる人は希少。AI導入支援で企業が一番恐れるのは事故。この保護設計を提案書に入れられるだけで信頼度が段違いになる。
  • 完成したsettings.jsonは再利用可能な商品（業種別・用途別の「AI安全設定パック」として展開できる）。
  • 「守りたいものの棚卸し→保護マップ→設定→検証」という手順は、セキュリティコンサルの標準プロセスそのもの。
