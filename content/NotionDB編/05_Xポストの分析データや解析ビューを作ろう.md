# 05_Xポストの分析データや解析ビューを作ろう（課題10-05）

## このページはなにを学ぶpage？
課題4で作った双方向リレーションのデータ（Posts DB×Authors DB）を使い、Notionの**「数式（フォーミュラ）」「ロールアップ」「チャート」の3機能でデータから意味のある情報を取り出す**分析の練習をする。NotionDB編の最終回。

## 重要ポイント
### Notionの数式は「行」単位（Excel経験者ほど注意）
- スプレッドシートは「セル単位」で式を書くが、**Notionは1つのプロパティ（列）に書いた式が全行に適用される**。これを「アレイフォーミュラ」と呼ぶ。

### 数式（Formula）：条件判定を作る
```
Authors DBにプロパティを追加してください。
双方向リレーションを対象としたarray formulaを追加する。
インプレッションが100以上のものを含む場合 true とする
```
- 各ユーザーの投稿に「インプレッション100以上が1つでもあればtrue」→**「人気投稿を持つユーザーか」をフラグで識別**できる。

### ロールアップ（Rollup）：関連DBの値を集計する
```
Authors DBにプロパティを追加してください。
双方向リレーションを対象としたRollupを追加する。
インプレッションの平均値を算出する
```
- ユーザーごとの平均インプレッションが一目でわかる。

### 数式とロールアップの使い分け
| 機能 | 用途 | 例 |
|---|---|---|
| 数式（Formula） | 計算ロジックで新しい値を作る | 「100以上ならtrue」の条件判定 |
| ロールアップ（Rollup） | 関連DBの値をまとめて集計 | 平均・合計・最大値・カウント |
- **迷ったら「何を計算したいか」だけAIに伝えれば、適切な機能を選んでくれる**。機能名を覚えるより目的を言語化する方が大事。

### チャートによる可視化
- Notion APIからはビュー追加が非対応→**チャートは手動で追加**（＋→チャート→Posts DBを選択）。
- 設定例：横棒／X軸=インプレッション数／グループ化=User ID／Y軸=いいね数
- 読み取り方：「最も右に伸びて高さもあるバーのユーザー＝**最もエンゲージメントが高い**」のように、**グラフから結論を言葉にする**練習が大事。
- 組み合わせ例：投稿数の多いユーザー（縦棒）／時系列の投稿傾向（折れ線）／ハッシュタグ別の比率（円グラフ）。
- 無料プランはチャート1つまで。

### 提出で問われること
- 「**その分析を選んだ理由**」を一言で説明する＝分析は目的（何を知りたいか）から始めるという姿勢。

## 用語解説
- **数式（フォーミュラ）**：計算式で新しい値を作るNotionのプロパティ。条件判定や文字加工に使う。
- **アレイフォーミュラ**：1つの式が列の全行にまとめて適用される仕組み。
- **ロールアップ**：リレーションでつながった別DBの値を「まとめ上げて」集計する機能。
- **プロパティ**：データベースの列（項目）。
- **フラグ**：true／false（はい/いいえ）で状態を示す目印。
- **true／false**：条件を満たす／満たさない。チェックボックスで表示される。
- **エンゲージメント**：投稿への反応の度合い（いいね・返信・保存など）。SNS分析の重要概念。
- **折れ線グラフ**：時間による変化（推移）を見るのに向いたグラフ。
- **相関**：2つの数値が連動して動く関係（インプレッションが多いといいねも多い、など）。

## マネタイズへのヒント💰
- **「データ→フラグ→集計→グラフ→結論」まで作れると、分析レポートサービスとして完結する**。SNS運用・EC運営・営業管理のどれでも同じ型が使える。
- 「人気投稿を持つユーザーの自動抽出」は、インフルエンサー選定・優良顧客抽出のロジックそのもの。**条件をフラグ化する発想**は営業リストの優先度付けなどに直結。
- NotionDB編全体（接続→書き込み→統合→ビュー→リレーション→数式→チャート）で、**NotionをCRM/業務システムとして構築代行できるスキルセット**が完成する。これは月額保守込みで受注しやすい商材。
