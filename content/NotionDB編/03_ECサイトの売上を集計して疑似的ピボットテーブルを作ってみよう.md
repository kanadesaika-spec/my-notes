# 03_ECサイトの売上げを集計して疑似的ピボットテーブルを作ってみよう（課題10-03）

## このページはなにを学ぶpage？
架空のカフェ事業の売上データ（30件）をNotionに書き込み、**小計・フィルター・グループ化・チャート**でいろいろな角度から集計する。最後はNotionに標準機能がない**ピボットテーブルを「疑似的に」作る**方法まで学ぶ。

## 重要ポイント
### 書き込み時の「列の型指定」が超重要
```
このCSVをNotionデータベースとして書き込んでください。
【書き込み先ページ】:（NotionページURL）
【Notion APIキー】: xxxx

# 列の型指定（重要）
- 売上金額 / 粗利益 / 数量 / 単価 / 仕入単価 → 数値型
- 受注日 → 日付型
- カテゴリー / チャネル / 地域 / ステータス / 担当者 → セレクト型
- 取引ID → タイトル型
```
- **数値を「文字列」で登録すると、後で合計も平均も計算できない**。データベース作りは最初の型指定が命。
- よくあるミス：APIキーをページに「接続」していないとエラー（ページ右上「…」→「接続」）。

### 小計機能（ヘッダー行を右クリック→計算）
- 合計・平均・最大値などがボタン1つで出る。※左クリックではメニューが出ない。
- **「値の数をカウント」＝全行数（重複含む）／「一意の値の数をカウント」＝重複を除いた種類数**（担当者4人など）。この違いは実務で頻出。

### ビューでの集計4パターン
1. **地域ごとの売上**：縦棒チャート（X軸=地域、Y軸=売上金額の合計）
2. **特定年月だけ抽出**：フィルターで「2025-10」を含む条件を追加
3. **売上の内訳**：グループ化（商品名でグループ化すると棒が色分けされ、どの商品がどこで売れたかわかる）
4. **売上TOP5**：ドーナツチャートに変更
- 無料プランはチャート1つまで（削除してから次を試す）。

### 疑似ピボットテーブルの作り方
- ピボットテーブル＝**縦×横の2軸でクロス集計する表**（例：縦=商品、横=月、値=売上）。Notionには標準機能がないので疑似的に作る：
	1. 集計用の新DBをAIに作らせる（項目：月・カテゴリー・商品名・売上金額）
	2. **双方向リレーション**で元の売上DBと取引IDでつなぐ
	3. ビューで「カテゴリーでグループ化」＋プロパティの表示/非表示・並び替えで、月×カテゴリーのクロス集計風に整える
	4. 取引IDにマウスを重ねて「開く」と元データの詳細も確認できる

### 分析の切り口のヒント（組み合わせ発想）
担当者×カテゴリー（誰が何を売る）／チャネル×月（オンラインvs対面の推移）／地域×商品名（地域ごとの人気）／ステータス×担当者（成約率）。**軸の掛け算でいくらでも分析は作れる**。

## 用語解説
- **EC（イーコマース）サイト**：ネット通販サイトのこと。
- **型（データ型）**：データの種類（数値・日付・文字など）。計算できるかどうかを決める。
- **セレクト型**：決まった選択肢から選ぶ項目の型（地域・担当者など）。
- **小計**：表の下部に出す合計・平均などの集計値。
- **一意（ユニーク）**：重複を除いた「種類」のこと。
- **フィルター**：条件に合うデータだけ表示する絞り込み。
- **グループ化**：同じ値のデータをまとめて表示する機能。
- **クロス集計**：縦軸×横軸の2つの切り口で集計する方法。ピボットテーブルの本質。
- **双方向リレーション**：2つのデータベースをお互いに参照し合う形でつなぐこと。
- **粗利益／粗利率**：売上から仕入コストを引いた利益／その割合（粗利益÷売上金額）。
- **チャネル**：販売経路（オンライン・対面など）。
- **前月比成長率**：前の月と比べてどれだけ増えたかの割合。

## マネタイズへのヒント💰
- **売上分析ダッシュボードの構築は、小規模EC・店舗への鉄板提案**。「売上データを送ってもらえば、見やすい分析ボードにして返す」サービスが成立する。
- 「型指定→書き込み→集計→クロス分析」の流れは、**顧客管理・在庫管理・案件管理などあらゆる業務DB構築に共通**。1回覚えれば横展開できる。
- 粗利率ランキングや前月比のような「計算指標」を出せると、単なる見える化ではなく**経営判断に使える提案**になり、単価が上がる。
