# 04_X APIを活用して X ポストをNotionにインポートしよう（課題10-04）

## このページはなにを学ぶpage？
X API（有料・最低5ドル）で**実際のXの投稿データを取得**し、Notionに「Posts DB（投稿）」と「Authors DB（投稿者）」の2つのデータベースを作って、**双方向リレーションで連携させる**。実務のデータ管理（顧客×取引×履歴の連携）に近い体験をする発展編。

## 重要ポイント
### 双方向リレーションとは（この課題のメインテーマ）
- 2つのデータベースを「**鍵となる項目**」（ここではユーザーID）でつなぐNotionの機能。
```
Posts DB（投稿データ）←── ユーザーIDで紐づけ ──→ Authors DB（投稿者データ)
```
- Authors DBでユーザーを開くと、**その人の投稿がすべて一覧表示される**。
- 実務では「顧客情報×取引情報×問い合わせ履歴」をこの形で連携させる。**これがCRM（顧客管理）の基本構造**。

### 費用と安全管理
- X APIはクレジット前払い（最低5ドル≒約800円、返金不可）。課題に必要なのは数十リクエスト程度なので5ドルで十分。
- **必ず「支出上限」を5ドルに設定**（しないと想定外の課金リスク）。
- **APIキーの取り扱い**：他人に渡さない・SNSに投稿しない・GitHubに公開しない（悪用→高額請求のリスク）。漏れたら即再発行。
- 費用をかけたくない場合は課題①のダミーデータで代用可。

### 手順の骨組み
1. **X Developer Portalでアプリ作成**→3つのキー（API Key／API Key Secret／Bearer Token）をコピー
2. **ポスト取得**：まずAIにAPIドキュメントを読ませてprompt yaml（取得手順の指示ファイル）を作らせ、それを実行してCSV化。**「ドキュメント読解→手順書作成→実行」の2段構え**がここでも登場
3. **Notionへ書き込み**：CSVを統合したPosts DBと、ユーザーIDだけのAuthors DBを作らせ、「双方向リレーションで接続してください」と指示
4. **確認**：Authors DBのユーザーページを開いて投稿一覧が表示されていれば完成

### チャレンジのヒント
取得項目を増やす（リプライ数・リポスト数）／フィルター・ソートで絞り込み／カレンダーやボードなど別ビュー／自動取得のスケジュール化。

## 用語解説
- **X API**：Xの投稿データをプログラムから取得・投稿できる有料の仕組み。
- **双方向リレーション**：2つのデータベースがお互いを参照し合う連携。片方に登録するともう片方にも自動で表示される。
- **鍵（キー）となる項目**：2つの表を結びつける共通の項目（ここではユーザーID）。データベース設計の基本概念。
- **Posts DB／Authors DB**：投稿データの表／投稿者データの表。「事実の記録」と「主体の一覧」を分けるのが設計の定石。
- **Bearer Token（ベアラートークン）**：APIの認証に使う長い合言葉。
- **prompt yaml**：AIに実行させる手順をYAML形式で書いた指示ファイル。再利用できる。
- **従量課金**：使った分だけ支払う方式。
- **支出上限**：使いすぎを防ぐための上限額設定。
- **ソート**：並べ替えのこと。
- **インポート**：外部のデータを取り込むこと。

## マネタイズへのヒント💰
- **「SNSデータ×顧客管理」の連携は、インフルエンサーマーケティングや営業リスト管理の実務そのもの**。見込み客のSNS発信を自動収集して顧客DBに紐づける仕組みは営業支援ツールとして売れる。
- 双方向リレーションの設計（何を鍵に、どの表を分けるか）は、**業務システム設計の入口スキル**。これができるとNotion構築代行の対応範囲が一気に広がる。
- 「上限設定・キー管理・返金不可の説明」といったコスト管理の知識は、顧客のAPIアカウントを預かる業務での必須リテラシー。
