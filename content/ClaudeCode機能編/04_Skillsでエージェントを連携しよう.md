# 04_Skillsでエージェントを連携しよう【入門】（課題3-04）

## このページはなにを学ぶpage？
複数の処理・複数のAIエージェントを**順番に自動で連携させる**方法を学ぶ。「ファイルを読む→要約する」の2段階から始めて、3段階のパイプライン、最終的には「分析→構築→検証」の実務的なワークフローまで作る。

## 重要ポイント
### 初級：2段階ワークフロー
```
Use Claude-Code-Guide
Skillsを作成してください
指定したファイルを読み込んで、タイトル・トピック（３つ）・結論の形式で要約して出力するコマンド
```
- **Claude-Code-Guide**＝最初から使えるSubAgentで、Claude Codeの正しい仕様（フォルダ構成やファイルの書き方）を知っている案内役。頭に付けて宣言すると正確なファイルを作ってくれる。
- 作成後は再起動→「/」を入力するとコマンド一覧が出る→ `/スキル名 ファイルパス` で実行。
- **出力形式を最初に決めておく**（タイトル・トピック3つ・結論）のが、安定した結果を得るコツ。

### 中級：3段階パイプラインに拡張
- ステップ3として「改善提案を3つ出す」を追加する
- 引数（実行時に渡す指定）を増やす：ファイルパスに加えて「要約の文字数」も指定できるようにする
- **エラーハンドリング**：ファイルが存在しないときどうするかを決めておく（実務では必須の考え方）

### 上級：Sequential Pipeline Pattern（順次実行パターン）
```
[Analyzer（分析）] → [Builder（構築）] → [Reviewer（検証）] → [完成]
```
- SubAgentを3つ定義し、順番に実行するコマンドを1つ作る。
- **「作る人」と「チェックする人」を分ける**のは、AIでも人間の仕事でも品質を上げる王道パターン。

### 知っておくべき注意点
- エージェントを連鎖させると**トークン消費（AIの利用量＝料金）が増える**。対策：各エージェントの出力を必要最小限にする／よく使うワークフローだけ自動化する。
- Skillsの中から別のSkillsを直接呼ぶことはできない（「次に /〇〇 を実行して」と指示文に書いて連続実行を促すことは可能）。
- 「/」でスキルが出てこないときは、`.claude/commands/` フォルダの場所・.md形式・再起動を確認。

## 用語解説
- **パイプライン**：処理を「流れ作業」のように順番につなげたもの。工場のベルトコンベアのイメージ。
- **Sequential Pipeline Pattern（シーケンシャル・パイプライン・パターン）**：「順番に1つずつ実行する」連携の型。マルチエージェント設計の基本パターン。
- **引数（ひきすう）**：コマンドを実行するときに渡す追加情報。`/summarize README.md` の「README.md」の部分。Skills内では `$ARGUMENTS` という書き方で受け取れる。
- **エラーハンドリング**：エラー（失敗）が起きたときの対処をあらかじめ決めておくこと。「ファイルがなければ〜と表示する」など。
- **トークン**：AIが文章を処理する単位。利用量＝料金に直結する。「トークン消費が激しい」＝コストが高くつく、という意味。
- **オーケストレーション**：たくさんのAIエージェントを指揮者のようにまとめて動かすこと。
- **CI/CD**：プログラムのテストや公開を自動で行う仕組み（継続的インテグレーション／継続的デリバリーの略）。開発現場の自動化技術。
- **awesome-claude-code**：Claude Codeの便利な設定やスキルを世界中の人が集めたGitHub上のまとめ集。

## マネタイズへのヒント💰
- 「分析→構築→検証」パイプラインは、**納品物の品質保証プロセスをAIで自動化する**という提案そのもの。制作代行サービスの差別化になる。
- 「トークン消費と自動化のバランスを考える」視点は、AI導入コンサルで必ず必要になる知識（費用対効果の説明ができる）。
- チームで共有できるワークフローを作る力は、「属人化しない仕組みの納品」として企業案件で高く評価される。
