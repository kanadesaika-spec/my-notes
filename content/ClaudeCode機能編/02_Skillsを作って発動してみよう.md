# 02_Skillsを作って発動してみよう【入門】（課題3-02）

## このページはなにを学ぶpage？
Claudeの「Skills（スキル）」＝**必要なときにAIが自動で読み込む「専門知識のパッケージ」**を作る方法を学ぶ。公式の「skill-creator」を使って対話形式でスキルを作り、発動させ、カスタマイズする。

## 重要ポイント
### Skillsとは
- 再利用できる機能のかたまり（モジュール）。「この作業のやり方」をファイルにしておくと、Claudeが必要な場面で自動的に読み込んで使う。
- **Progressive Disclosure（段階的情報開示）**という仕組みがミソ：普段は名前と説明だけを見ておき、必要になったときだけ中身を読み込む。だからスキルをたくさん持ってもAIの記憶（コンテキスト）を圧迫しない。
- 「グローバル（全プロジェクト共通）」と「プロジェクト固有」の2種類がある。初心者はプロジェクト固有がおすすめ。

### 作り方
1. 公式のスキル作成支援ツールを入れる：
```
Anthropic公式スキルの skill-creator をインストールしてください
https://github.com/anthropics/skills
```
2. 作りたいスキルの仕様を伝える（例は文字数カウントスキル）
3. `.claude/skills/スキル名/SKILL.md` が生成される
4. **アプリを再起動**してから「〇〇スキルを使って…」で発動確認

### SKILL.mdの構造
- YAMLフロントマター（name／description）＋ Markdownの指示文、というシンプルな構造。ただのテキストファイルなので手でも編集できる。

### 発動精度を上げるコツ（中級）
- **descriptionの書き方がすべて**。曖昧だと自動発動しない。
	- ✅「MUST BE USED when user sends a greeting」（〜のとき必ず使う）
	- ✅「Use PROACTIVELY for email writing tasks」（〜の作業では積極的に使う）
	- ❌「A skill for greetings」（曖昧すぎてダメ）

### 管理とセキュリティ
- スキルの説明文は合計15,000文字以内という制限がある。似たスキルは統合、使わないものは削除。
- SKILL.mdは簡潔に（500行以下推奨）、詳細は reference.md という別ファイルに分ける。
- **他人が作ったスキルは中身を確認してから入れる**。特にスクリプト（プログラム）入りのスキルは実行前に必ずチェック（公式も「信頼できるソースからのみ」と推奨）。

## 用語解説
- **Skill（スキル）**：Claudeに追加できる「技・手順書」。`/スキル名` やAIの自動判断で発動する。
- **モジュール**：機能ごとに分かれた部品のこと。組み合わせて大きな仕組みを作れる。
- **Progressive Disclosure（プログレッシブ・ディスクロージャー）**：「段階的情報開示」。最初は目次だけ見せて、必要なときに詳細を開く方式。AIの記憶容量を節約する重要な設計思想。
- **skill-creator（スキルクリエイター)**：Anthropic公式の「スキルを作るためのスキル」。対話しながらスキルを自動生成してくれる。
- **メタデータ**：データについてのデータ。「このスキルの名前・説明・作者」のような、中身を説明する情報。
- **テンプレート**：ひな形のこと。毎回同じ形式で出力させたいときに用意しておく。
- **スクリプト**：小さなプログラムのこと。スキルに.pyファイル（Python）などを含めて、計算や処理をさせられる。
- **リポジトリ**：GitHubのプロジェクト保管箱。公式スキル集は https://github.com/anthropics/skills にある。
- **監査**：中身に危険がないか確認・チェックすること。

## SubAgentとの違い（超重要な整理）
- **SubAgent**＝専門の「担当者」を作る（独立した頭で働く分身）
- **Skill**＝専門の「マニュアル」を作る（必要なとき読み込まれる手順書）
- 組み合わせると「マニュアルを持った専門担当者チーム」が作れる。

## マネタイズへのヒント💰
- **よくやる業務をスキル化したものは、それ自体が商品になる**（例：「請求書作成スキル」「SNS投稿作成スキル」を業種別に作って提供する）。
- 導入支援サービス：企業の定型業務をヒアリングしてスキル化してあげる「AI業務マニュアル化代行」は需要が大きい。
- Progressive Disclosureの考え方（必要な情報だけ渡す）は、AIのコスト削減（トークン節約）にも直結する実務知識。
