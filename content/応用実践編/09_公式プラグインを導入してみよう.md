# 09_公式プラグインを導入してみよう【実践】（課題4-09）

## このページはなにを学ぶpage？
Claude Codeの「プラグイン」＝**便利機能の詰め合わせパック**の仕組みを理解し、Anthropic公式のマーケットプレイス（カタログ）から公式プラグインを1つインストールして使えるようにする。難しい設定は不要で、メニュー操作とコマンド1〜2行で完結する。

## 重要ポイント
### プラグインとは
- スキル・サブエージェント・フック・MCPサーバーなどの拡張機能を**1つのフォルダにまとめた配布パッケージ**。
- 誰かが作った便利機能を、ゼロから設定せず「インストールするだけ」で使える。

### プラグインに入れられる4つの要素
| 要素 | これは何か | 例 |
|---|---|---|
| スキル/コマンド | 新しい「やり方」の説明書 | コミットメッセージ作成、PR作成 |
| サブエージェント | 特化型の小さなAI担当者 | コードレビュー専門、セキュリティ確認専門 |
| フック | タイミングで自動的に動く仕掛け | 保存したら自動チェック |
| MCPサーバー | 外部サービスとの連携口 | GitHub・Slack・Notionとの接続 |

### マーケットプレイスの2段階の仕組み（アプリストアと同じ）
1. **マーケットプレイス（カタログ）を追加する**（この時点では何も入らない）
2. **カタログから個別にプラグインをインストールする**
- 公式マーケットプレイス「claude-plugins-official」は**最初から登録済み**なので、いきなり選んでインストールできる。

### 名前空間の仕組み
- プラグイン由来のスキルは `/プラグイン名:スキル名` の形で呼び出す（例：`/commit-commands:commit`）。
- 複数のプラグインに同名スキルがあっても衝突しないための仕組み。この形でコマンドが増えていれば導入成功の証拠。

### 導入の流れ（例：commit-commands）
1. メニューの「カスタマイズ」→「追加」→「プラグインを参照」
2. 検索窓で探してインストール→**アプリを再起動**
3. `/commit` と打って `/commit-commands:commit` が候補に出ればOK

### 安全性の注意
- **プラグインは自分のパソコン上でコードを実行できる強い仕組み**。信頼できる提供元のものだけ入れる。よく分からない第三者のマーケットプレイスを安易に追加しない。

## 用語解説
- **プラグイン**：後から追加できる拡張機能のパック。
- **マーケットプレイス**：プラグインを配布するカタログ（お店）。アプリストアのようなもの。
- **claude-plugins-official**：Anthropicが管理する公式マーケットプレイス。
- **commit-commands**：Gitのコミット作業（変更の記録）を手伝ってくれる公式プラグイン。
- **名前空間**：名前の衝突を防ぐための「所属表示」。`プラグイン名:スキル名` の形式。
- **MCPサーバー**：AIと外部サービス（GitHub・Slack・Notionなど）をつなぐ標準的な連携の仕組み（Model Context Protocol）。
- **LSPサーバー**：プログラミング言語の文法理解を助ける仕組み（Language Server Protocol）。
- **リポジトリから追加**：GitHubのURLを指定してマーケットプレイスを登録する方法。
- **同期**：カタログの最新情報を取り込むこと。

## マネタイズへのヒント💰
- **「配布する側」に回れるのが最大のチャンス**：自分が作ったスキルやエージェントの詰め合わせをプラグイン化して配布・販売できる（業種特化パック、SNS運用パックなど）。
- 公式プラグイン（security-guidance、github、pr-review-toolkitなど）を使いこなせると、開発・納品の品質と速度が上がる＝受託の利益率が上がる。
- 「信頼できる提供元しか入れない」というリテラシーは、顧客環境に導入するときの説明責任として必須。
