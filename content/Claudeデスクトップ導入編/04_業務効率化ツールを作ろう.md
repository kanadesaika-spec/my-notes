# 04_業務効率化ツールを作ろう（課題1-04）

## このページはなにを学ぶpage？
ホームページの「裏側」で動く業務システム（お客様管理や承認の画面など）を、AIに作ってもらう方法を学ぶ。本物のサービスとはつなげず、見た目と操作を体験できる「モック」（試作品）を作る。

## 重要ポイント
- **表側と裏側はセットで考える**：お客様が見るホームページ（表側）と、お店の人が使う管理システム（裏側）がつながって、初めてサービス全体になる。
- **モックで十分イメージは伝わる**：最初から本物を作らなくても、動く試作品があれば「どんなサービスか」をお客様や仲間に見せられる。
- **完成したら実際に操作して確認する**：サンプルデータが出るか、タブを切り替えられるか、登録・編集・承認ができるか、画面同士で情報が引き継がれるか。
- **改善も日本語でOK**：「承認の流れを3段階にして」「グラフを追加して」「初めての人向け説明を付けて」など何度でも頼める。
- 業務テーマを変えたいときは、プロンプトの1行目を書き換えるだけでよい。
- **承認制＋非承認理由の記録→ナレッジ化**という例文は、実務でとても使える考え方（AIの回答を人がチェックし、ダメだった理由をためて賢くしていく仕組み）。

## 覚えておきたいプロンプト（お手本）
```
先ほど作ったホームページの裏側のシステムを作って下さい

仕様駆動MVP=level3。out:図解PNG+動くHTML単一(localStorage/JP/白)・5tab・100点+3層振分・sample5-15・各画面🤖pt・承認段階ゲート引継型・モーダル(confirm禁止)・STORE_KEY昇格・中規模A2A→open(フルパス+説明)

どのような指示であっても必ずモックとして
「凄い！」と思うような業務効率化ツールにして下さい。
サービス連携などは一旦行わずイメージをみたいです！急ぎで！
完成したらブラウザでサイトOpen
```

テーマを変える例：
```
LINEの返信文を自動化するサービスを作ってください。返信は承認制とし、非承認の場合は理由を記録し、その内容がナレッジとして蓄積される仕組みにしてください。
```

## 用語解説
- **業務効率化ツール**：仕事の作業（予約管理・在庫管理・お客様対応など）をラクにするための道具（システム）のこと。
- **モック**：見た目と操作だけ体験できる「試作品」。中身は本物とつながっていないが、完成イメージを確認するのに使う。模型のようなもの。
- **MVP（エムブイピー）**：「Minimum Viable Product」の略。「必要最小限だけど使える製品」のこと。最初から完璧を目指さず、小さく作って試すのが今のサービス作りの主流。
- **仕様駆動**：先に「仕様」（何をどう作るかの決めごと）をはっきりさせてから作る進め方。
- **タブ**：画面上部の切り替えボタン。ノートのインデックスシールのように、画面を切り替えられる。
- **localStorage（ローカルストレージ）**：ブラウザの中にデータを保存しておける小さな保管庫。サーバーがなくてもデータを覚えておける。
- **承認フロー**：「作ったものを上司がチェックしてOKを出す」ような、確認の流れのこと。
- **ナレッジ**：仕事で役立つ知識やノウハウのこと。失敗理由をためて次に活かす「知識の貯金」。
- **ダッシュボード**：大事な数字やグラフを1つの画面にまとめた「運転席のメーター」のような画面。
- **モーダル**：画面の上にポンと重なって出てくる小さな確認ウィンドウ。
- **サンプルデータ**：動作確認用のニセモノのデータ。本物のお客様情報の代わりに入れておくもの。

## マネタイズへのヒント💰
- **「ホームページ＋裏側の業務システム」をセットで提案できると単価が大きく上がる**。ホームページ制作だけなら数万円でも、予約管理・顧客管理まで含めると数十万円の案件になり得る。
- モックを先に作って見せる営業は強力：「こんなシステムはどうですか？」と動くものを見せられると、お客様は具体的に検討できて契約につながりやすい。モックはAIで数分で作れるので、営業コストがほぼゼロ。
- 「承認制＋理由の記録＋ナレッジ蓄積」の仕組みは、AI代行サービス（返信代行・投稿代行など）を売るときの信頼の担保になる。
